AI-driven testing

I treat AI as a working part of the test process, not a gimmick. Each piece below exists in my Grafana suite, and each one is built so a wrong answer from a model cannot break a test run.

Exploratory testing agent

An LLM agent drives a real browser through a small set of tools, explores the product and reports what it finds, the way a tester would on a first pass.

AI failure analysis

When a test fails, the error text, the URL and the page's accessibility snapshot go to a model that explains the likely cause, so triage starts with a hypothesis.

AI run reports

Allure results are turned into a readable HTML report with findings and suggested improvements. It works rule-based with no model at all, and gets richer when a model is available.

AI-assisted development

I use AI assistants to design and write code, then review it and prove it by running it: tests, CI and real failure output decide what is correct, not the model's confidence.

  • Provider-agnostic: works with a local model through Ollama, any OpenAI-compatible endpoint, or the Anthropic API, and defaults to no provider so it costs nothing to run.
  • Safe by design: a call budget caps usage, AI steps skip cleanly when no provider is set, and analysis never decides whether a test passes.

AI-driven test automation

Grafana Test Automation Suite

A complete automated test suite for Grafana 13, written to cover real business flows rather than just a login page. It runs locally, in Docker and in GitHub Actions, and it is green on Chromium, Firefox and WebKit.

  • 107 desktop tests across UI and API: dashboards (create, edit, delete, import, variables, time range), folders, alert rules, users, roles, teams and folder permissions.
  • Mobile web tests with Appium on an Android emulator (8 tests).
  • Clean architecture: Page Object, Builder and Facade patterns, data-driven tests from CSV and SQLite, and a cleanup tracker so every test removes what it creates.
  • Reporting: Allure reports with steps, traces and videos, plus an HTML report that analyses each run and suggests improvements.
  • AI agents: an exploratory-testing agent, AI failure analysis and AI-written run summaries. They work with Ollama, any OpenAI-compatible endpoint or the Anthropic API, and everything still runs with no paid API and no AI provider at all.
  • CI/CD: Docker image, GitHub Actions matrix across three browsers, and a scheduled nightly run.

DevOps tooling

DevOps Terminal Commander

A desktop app that turns the commands I use every day into one-click buttons. Pick a command, fill in any missing values in a dialog, and the app runs it in your shell and streams the output back.

  • Command library for Linux, Git, Docker and Kubernetes, with 25 Git commands alone.
  • Parameter dialog: commands with placeholders such as {commit_message} or {service_name} open a focused form before anything runs.
  • Built-in explanations: hover over any command to see what it does.
  • Live console that shows the command output as it arrives.
  • Two-process design: a sandboxed UI that talks to the Node.js core only through a context bridge (IPC).
